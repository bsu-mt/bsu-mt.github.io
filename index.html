Revit → Unity → HoloLens 2 pipeline

Three projects, one workflow: a live Revit model is exported and streamed over WebSocket, picked up and turned into a Unity asset, then deployed to HoloLens 2 for spatial, in-context review with Life Cycle Assessment data attached.

01

Export & stream

Revit Exporter to WebSocket Server

C# · Revit API · WebSocket

A Revit add-in that adds a custom Unity & Revit Transfer ribbon tab with an Export OBJ command. On click, it exports the active document's first non-template 3D view to .obj/.mtl using the Revit API, then streams both files to an external WebSocket server in 8 KB chunks.

  • Custom ribbon UI built via IExternalApplication, defined in APP.cs.
  • ExportButton.cs handles the 3D-view export and chunked upload over a raw WebSocket connection (websocket-sharp).
  • A second, independent IExternalApplication (RevitWebSocketClient.cs) opens its own WebSocket connection at startup — reserved for future live document-change syncing; currently experimental.
  • Targets Revit 2026 / .NET Framework 4.8, built in Visual Studio.

02

Receive & load

Unity Importer from WebSocket Server

C# · Unity Package · WebSocket

The Unity-side counterpart: a package (WebSocketConnector) that connects to the same WebSocket server, lists the OBJ/MTL files available, downloads a selection, and loads it straight into the scene at runtime — no manual import step.

  • OBJImporter.cs owns the WebSocket connection, downloads the OBJ/MTL pair, and loads it with a bundled runtime OBJ/MTL importer (Dummiesman).
  • Parses .mtl diffuse color (and optional diffuse texture) and rebinds it onto the loaded mesh's renderers.
  • Dockable Window → WebSocket Connector Editor panel to connect, list remote files, and load by selection or by name without writing code.
  • Editor-only prefab export — saves the runtime-loaded meshes/materials as real project assets and connects them into a reusable prefab.

03

Visualize in MR

HoloLens Viewer for Unity

C# · Unity · HoloLens 2 · Mixed Reality

The prefab the Unity importer produces — a Revit-exported circular-economy steel structure — is deployed to Microsoft HoloLens 2 as a spatially anchored, interactable object, with Life Cycle Assessment (LCA) data attached for in-context review.

  • Built on Microsoft's Mixed Reality Toolkit (MRTK3) plus Unity's XR Interaction Toolkit for hand/gaze interaction and spatial UI.
  • An OpenUrlButton component wires a UI button to open an external link — e.g. an LCA report or data source — from inside the scene.
  • Builds to Universal Windows Platform and deploys over USB or Wi-Fi via Device Portal, or runs in the HoloLens emulator.
  • Depends on the MRTK3 org.mixedrealitytoolkit.* packages, restored via Microsoft's Mixed Reality Feature Tool.

In development

RobotStudio → Unity → Quest 2 pipeline

An active research & prototyping project: exporting an ABB RobotStudio robot-arm assembly simulation — geometry, joint motion, and I/O signal timelines — into a package a Unity app can play back interactively on Meta Quest 2, for reviewing an automated assembly sequence away from the robot itself.

01

Export (research & prototyping)

RobotStudio Exporter for Unity

C# · RobotStudio SDK · FreeCAD

A planned RobotStudio add-in that packages a station's per-link geometry, joint motion timeline, and I/O signal timeline into one Unity-importable export — in a single export action, for any RobotStudio station, not one hardcoded demo.

  • The joint motion and signal timelines don't exist as exportable files in RobotStudio — they're transient simulation state, so capturing them means hooking the SimulationController/Mechanism and IOSystem signal-changed events programmatically while the simulation plays.
  • Geometry conversion is a two-stage pipeline under the hood: RobotStudio-side per-link export (STEP), then an automated FreeCAD pass into a Unity-friendly format (FBX/glTF) — one action from the user's perspective.
  • Also captures a joint-hierarchy manifest (parent/child structure, offsets, axes, limits) so the Unity side can reassemble a correctly-jointed rig without hand-authoring it.
  • Status: skeleton only. No RobotStudio API integration code yet — next step is confirming which ABB.Robotics.* DLL set an add-in needs before building the real export logic.

02

Import & playback (test harness)

Unity Importer from RobotStudio

C# · Unity 6.3 LTS · Meta Quest 2 · OpenXR

A Unity/Quest 2 test harness that will import the exporter's package and play the assembly sequence back interactively — play, pause, and step through it, with live inspection of every tracked I/O signal at any point in time.

  • Built on Unity 6.3 LTS (URP), targeting Meta Quest 2 via OpenXR + the Meta XR SDK.
  • Current demo data is deliberately placeholder: an IRB4600 stands in for the target IRB5720 hardware, motion is linear-interpolated between start/end joint angles (flagged in code as PlaceholderLerpJoints) pending real waypoint data, and signal timing is hardcoded pending a real signal export — all structured to match the eventual export schema so real data can drop in later.
  • Status: early / v0. Project skeleton is done — XR rig, ground plane, and an Editor-only XR Interaction Simulator for testing without a headset. Import logic, rig assembly, timeline playback, and the signal panel UI haven't been started yet.
  • On-device Quest 2 builds are blocked until Android Build Support is added to the Unity install — currently Windows Standalone only.

Other projects

Standalone tools outside the pipelines above.

RevitQC

pyRevit · Python

A pyRevit extension that adds one-click model-QC tools to Revit's ribbon, built around a Canadian HVAC (mechanical) project naming convention. Turns checks that don't scale by hand — naming violations, non-standard duct/pipe sizes, missing equipment tags — into a ribbon button that can be run before every handover or coordination meeting.

  • NameChecker — validates HVAC type names (equipment, air terminals, ducts, pipes) against configurable regex rules in rules/naming_rules.json, e.g. AHU-01, SA_RECT_600x300mm. Reports violations in a markdown table.
  • SizeChecker — flags duct/pipe sizes that don't match an approved standard sizing table in rules/size_rules.json (e.g. round ducts must be one of 100/125/150/…/900 mm).
  • EquipmentChecker — flags mechanical equipment missing a tag (Mark), and air terminals missing a tag or with zero/blank airflow.
  • Checking logic (core_checker.py, size_checker.py) is Revit-independent and unit tested — each has a standalone test runner (tests/sample_data.py, tests/sample_size_data.py) that exercises it against mock data with no Revit installation required.
  • Every rule set is a plain, editable JSON file, so the checks adapt to a different project's BIM execution plan without touching code.
